# V5 security and limitations

Revision: v5-r1. Audience: security reviewers/operators. Authorization: project-local implementation; separate exact owner approval for every remote mutation. Inputs: reviewed contracts and owner-supplied authorized files. Original code and text; external source rights remain per-source and per-approval.

Only the dedicated publisher module reads the three fixed Linux service credential names: key, expiry metadata and tenant binding. It uses `O_NOFOLLOW`, regular-file/size/link/permission checks and rejects cross-tenant binding before reading the key. Known expiry is enforced. The owner's 2026-10-24 direction to proceed without a supplied expiration permits an explicit `UNKNOWN_OWNER_ACCEPTED` sentinel; malformed/absent metadata remains blocked. This exception does not certify unlimited validity or provide a rotation forecast. The operator-only masked terminal helper refuses pipes, symlinks, unsafe parents, checkout storage and overwriting existing sets. No `.env`, global auth home, SSH material, cookies, raw environment dump or key argv is used. Tokens never enter tenant databases, artifacts, model inputs or research parsers. Authorization is redacted and provider errors are reduced to fixed codes without raw response bodies. Redaction patterns do not guarantee detection of every arbitrary key; avoiding secret ingestion into logs remains mandatory.

Authenticated egress permits HTTPS Buffer's root GraphQL endpoint only. Public proof permits HTTPS `publish.x.com/oembed` only and receives no Buffer credential. DNS results must all be public and the selected address is pinned through TLS hostname validation. No redirects, compression, arbitrary host/port, credentials in URLs, unbounded body, mutation retry loop or proxy automation is supported. Transport uses a 20-second request deadline and 2 MiB response ceiling. Budget reservations survive request failures and restart. Missing schema/coverage/permission/cost identity fails closed.

Tenant/dataset stores, safe paths, file modes, immediate job/channel leases, immutable approval/attempt/receipt events and audit-projection checks prevent accidental crossing and duplicate retries within the local trust boundary. A provider timeout does not prove rejection. Unknown acceptance blocks resubmission. Local hashes are integrity bindings, not digital owner signatures; process/account security and genuine owner confirmation are operational prerequisites. A user with unrestricted host write access can replace code or stores; this implementation does not claim to defeat that adversary.

External manual scheduling can race a queue read; the provider's hard capacity and explicit error/reconciliation handling remain final. An approval revoked after Buffer accepts a future post does not magically cancel it: report HOLD and obtain cancellation authority, then confirm the remote pending post was cancelled. Never claim `CANCELLED` from a local flag. A network cancellation timeout requires inspection before further actions. Unsupported media hosting is blocked, even with valid local rights.

Source material, public embed HTML and search snippets are untrusted data. No embedded scripts execute and no retrieved instructions can authorize writes. Existing first-person attestation and high-risk claim rules remain in force. Post metrics and product exports retain their separate verification classes; missing data cannot become zero or a growth claim.

`pnpm check` runs compiler/lint, all deterministic regressions, governance, Python tests, Gitleaks and local Semgrep. The V5 tests cover identity mismatch, GraphQL unions/errors, outages, capacity, concurrency, uncertain writes, DST, approval/source changes, metrics lag, public author/content mismatch and restore. Dedicated scanner rules reject V5 network imports/calls and credential environment reads outside the reviewed transport; a real Semgrep regression scans denied worker code without executing it. `pnpm audit --prod --json` adds registry dependency evidence separately from offline tests.

The registry audit found the existing Satori dependency `fflate@0.7.3` vulnerable to [GHSA-px8p-9vwx-vf98](https://github.com/advisories/GHSA-px8p-9vwx-vf98). A narrow pnpm override selects patched `0.7.5`; renderer regressions remain required. `twitter-text@3.1.0` supplies X weighted character parsing (Apache-2.0). Its deprecated core-js dependency is disclosed; the registry audit found no associated known advisory at this check. A clean audit is not a guarantee of no vulnerabilities.

Live key revocation, actual Buffer write permissions, actual X delivery and public proof remain unverified until genuine credentials/owner approval are supplied. Global hook timing was not diagnosed through credential-bearing configuration. Nothing modifies or disables security hooks or global model/provider authentication.
