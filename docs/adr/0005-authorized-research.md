# ADR 0005: authorized files and governance-scoped planning

Status: implemented Phase C. Inputs: owner-requested phased plan, source trust policy and brand claim restrictions. Audience: local implementers. No external assets or public authorization.

Keep live fetching outside the runtime for this slice. Accept strict, tenant-scoped inbox files; compare local contracts to actual allowed brand bytes and preserve supplied public excerpts as unverified. Store typed source cards inside the existing immutable source body so schema revision 1 and historical B records remain readable.

Do not treat a first-party source label, caller-provided verification status or ledger text as semantic proof. The planning generator uses governance evidence for editorial constraints, declares audience/topic hypotheses and emits no public factual claims. Briefs identify the missing topic proof. This yields reviewable plans without fabricating product/founder support; independently reviewed factual drafting remains a later capability.

Keep upstream skill bodies as optional namespaced references; canonical project skills own routing and permissions. Verify body/license pins before local planning. No upstream scripts, linked dependencies or scheduler routes activate. Pattern-based injection rejection helps review, but the structural boundary—no source execution, prompt routing or source-to-copy interpolation—remains the authority control.

Use actual time for ingestion/freshness. Record a fixed evaluation clock for reproducible sample replay in isolated state; that replay never makes historical evidence current. Changed contracts become stale, and new immutable revisions supersede them for selection. Expiry at future calendar dates is an explicit refresh dependency.

Tradeoff: deterministic local plans can be audited and replayed without credentials, provider charges or private collection, but they cannot establish market demand, live product behavior or founder history. Outputs preserve inputs, references, revisions, approval/asset status and limits. Validation: Phase C runtime negatives, two-tenant samples and verify_phase_c.py receipts.
